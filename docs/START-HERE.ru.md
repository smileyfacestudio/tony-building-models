# Сава — как начать работу

[English version](START-HERE.en.md) · [Главная страница проекта](../README.md)

## 1. Скачай проект

Открой [публичный репозиторий](https://github.com/smileyfacestudio/tony-building-models). Чтобы читать его, вступать в GitHub-организацию SFS не нужно.

Самый быстрый вариант без Git: нажми **Code → Download ZIP**, распакуй архив и сохрани папку на своём компьютере. Это рабочая копия файлов, но без истории Git и удобной отправки/получения обновлений.

Для постоянной совместной работы лучше клонировать репозиторий по ссылке через GitHub Desktop. Если Git уже установлен, можно выполнить:

```sh
git clone https://github.com/smileyfacestudio/tony-building-models.git
cd tony-building-models
```

В [официальной инструкции GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository) описаны варианты через приложение и командную строку.

## 2. Открой свою копию в Codex

Используй свой установленный Codex и свой аккаунт. В приложении добавь/открой скачанную или клонированную папку `tony-building-models` как локальный проект и создай в нём задачу. Если есть переключатель ChatGPT/Codex, для работы с репозиторием выбери Codex. Если работаешь через Codex CLI или расширение редактора, открой там эту же локальную папку.

Если нужна помощь с установкой или входом, используй [официальную инструкцию OpenAI](https://learn.chatgpt.com/docs/quickstart). Названия кнопок могут отличаться в разных версиях. На этапе инструкций и шаблонов не нужны доступ к внутреннему хранилищу SFS, общий аккаунт, API-ключ, установка Node.js или сборка приложения. Никому не передавай данные своего входа.

## 3. Дай своему агенту первое задание

Скопируй этот текст в задачу Codex:

```text
Я Сава, консультант по инженерной инфраструктуре в этом проекте SFS.
Общайся со мной по-русски, если я не попрошу английский. Прочитай AGENTS.md,
README.md, docs/project-brief.md, docs/capture-guide.md и docs/data-dictionary.md.

Сначала кратко объясни, что уже есть, чего не хватает и что ещё не проверено.
Задай мне до пяти практических вопросов о границах работ и задачах по
электрике/сетям на объектах CV255 и NC3007. Помоги составить чек-лист
обследования и структуру предварительной сметы. Не придумывай размеры,
скрытую проводку, количества, цены или выводы о соответствии нормам.

Репозиторий ПУБЛИЧНЫЙ. Не проси конфиденциальные фото или сведения об объекте
в открытом issue. Прежде чем сохранять фактические данные объекта, уточни
у меня согласованное закрытое место работы. Оставь публичные шаблоны пустыми;
не коммить и не публикуй материалы обследования, цены для клиента, закрытые
ссылки или секретные данные. Без моего запроса не отправляй изменения,
не приглашай пользователей, не обращайся к третьим лицам и не меняй
видимость репозитория.
```

## 4. Первый результат работы

Начни с одного объекта и определи:

1. Какие этажи, помещения и зоны входят в работу.
2. Что уже существует, а что нужно добавить: розетки, линии питания, сетевые точки, Wi-Fi, стойки, кабельные трассы или другие системы.
3. Какие планы, фотографии, видео и обмеры ещё нужны.
4. Что можно оценить по имеющимся данным, а где нужны обследование, проверка, предварительный резерв или исключение из сметы.
5. Как будет устроена первая версия сметы — без выдуманных цен и количеств.

Перед выездом прочитай [чек-лист съёмки и обмеров](capture-guide.md). Пустые CSV из `templates/` можно скопировать в согласованное закрытое рабочее пространство и открыть в Excel, другом табличном редакторе или Codex. Не меняй названия столбцов и идентификаторы. Не заполняй публичные копии фактическими данными объекта.

## 5. Как передавать изменения

- Для чтения и скачивания достаточно ссылки — приглашение не нужно.
- Для внесения безопасных публичных изменений отправь Борису свой логин GitHub личным сообщением. Он сможет дать доступ Write именно к этому репозиторию. В рамках этого стартового пакета приглашение ещё не отправлено.
- Когда доступ появится, создай отдельную ветку, например `sava/intake-checklist`, проверь изменения и открой pull request — запрос на их принятие после проверки SFS. Не отправляй изменения напрямую в `main`.
- Реальные фото/видео, подробные схемы, цены и данные клиента храни в согласованном закрытом пространстве. Папка на твоём компьютере не синхронизируется с Борисом автоматически: сначала согласуйте способ передачи.
- Доступ к этому проекту не даёт доступа к внутреннему хранилищу SFS. Его подключим отдельно позже.

**Результат первого дня:** проект открыт в твоём Codex, агент понимает оба идентификатора объектов и границы публичного репозитория, список первых недостающих материалов готов, а Борис знает твой логин GitHub, если нужен доступ на запись.
